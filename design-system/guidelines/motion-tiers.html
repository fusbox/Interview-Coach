Motion explains cause and effect

Motion should make state changes legible: a control acknowledges input, a surface lifts because it is interactive, an overlay enters from the object that opened it, and session content stays calm enough to support focus.

Semantic motion roles

Role
Token set
Use
Control
--motion-control-duration
Buttons, chips, tabs, switches and avatar-style launchers. Fast response; no lingering fade.
Surface
--motion-surface-duration
Cards and widgets lift, settle or change boundary. Movement is small and paired with elevation.
Feedback
--motion-feedback-duration
Selected, queued, saved and validation states. Prefer opacity, border, ring or fill changes.
Overlay
--motion-overlay-duration
Dialogs, sheets, popovers and coach-update panels. Opacity plus a short translate; no bounce.
Page
--motion-page-duration
Route or section reveal. Use sparingly; layout must remain stable while content appears.
Reduced motion
prefers-reduced-motion
Replace movement with instant state, opacity, border, color or focus-ring change.

Interaction state contract

Default

Still. No constant motion for ordinary resting UI.

Hover

Lift at most 2px and raise one depth tier.

Press

Scale to .98 or settle downward, then return fast.

Selected

Use ring, border, fill or label change more than motion.

Reduced motion

No translate or scale. State changes remain visible.

Core session

Only functional motion: recording, turn-taking, reveal.

Implementation rule: choose a semantic motion role before choosing a transition. If the motion cannot be explained as feedback, hierarchy, continuity or focus support, remove it.
