Candidate dashboard composition wireframes

The first viewport is anchored by two linked widgets: Coach Update and Next Round Plan. Their heights trade priority based on whether the latest coach update is unread or reviewed, while the dashboard footprint stays stable.

Composition principles

Linked priority

The two widgets are visually separate but state-linked. One expands while the other compresses.

Plan starts practice

The candidate can start only from the Added bucket inside the expanded Next Round Plan.

Questions stay compact

Practice items show Q#, category color and question text. No prep state or extra chrome inside the row.

Stable footprint

The dashboard should not jump when items move. Buckets scroll sideways when content exceeds visible width.

Mobile order

Header, linked coach/plan stack, progress-to-mastery, focus pivots, recent practice. The expanded widget owns the viewport; supporting content follows.

Plan-only state

When there is no new coach update, the coach widget stays collapsed as Last coach update and the Next Round Plan remains expanded.

Interaction model

Tapping a recommended item moves it into Added. Tapping an Added item returns it to Recommended. Practice begins only from the Added bucket.

Composition risk

Horizontal strips must reveal partial next items and counts so hidden questions do not feel lost. The parent widget should keep its height while strips handle overflow.

Pattern definition

Role Context Popover combines the native-hover-card surface behavior with the current role switcher content model. It is identity-adjacent, but role-first.

Interaction contract

Tap/click opens downward from the avatar + role trigger. Selecting a saved role closes the surface and reloads the dashboard context. Prep for a new role routes to setup.

Do not treat as profile first

The footer exits back to RangamWorks. The first information scent must be the active prep role and available role contexts.

Coach avatar role

The coach avatar opens reference-based coach plan guidance: category coverage, category definitions, why the category matters in an interview, skill lane explanations, dimensions, and best response patterns.

Modal dismissal

Top-level modal surfaces click away or tap away. A second nested surface uses a back arrow in the upper left to close back to the parent modal and does not click away.

Decision log and open questions

Decisions captured
  • Nested dashboard widgets use the 16px --radius-widget tier; standard outer dashboard surfaces use the 24px --radius-card tier.
  • Coach Update and Next Round are separate stacked widgets with linked priority states.
  • The app frame gap is 12px, matching the gap between linked widgets and support cards.
  • The user avatar plus current role text is the header trigger for role context.
  • Role Context Popover uses a native-hover-card shell and the existing role switcher content model.
  • Current active role is sticky above the saved-role list.
  • Show three saved roles before the saved-role list scrolls.
  • Role rows show last practiced date only; prep state is communicated by the visual badge/gauge.
  • Saved roles sort by descending last practiced date; never-practiced roles fall after dated roles.
  • Empty state for no saved roles shows only + Prep for a new role.
  • Current role block is context only, not a link.
  • Footer action is <- Back to RangamWorks linking to https://rangamworks.com/portal/home.
  • Mobile role context opens as an anchored sheet below the header trigger.
  • Top-level modal surfaces close on clickaway/tapaway.
  • Second nested surfaces use an upper-left back arrow to return to the parent modal and do not close on clickaway/tapaway.
  • Coach avatar remains right-aligned and opens the coach reference layer, not role switching and not the Coach Update action loop.
  • Coach reference layer covers Coach Plan framing, category coverage, category definitions, interview purpose, skill lanes/dimensions, best response patterns, and evidence-safe learning guidance.
Need from product/design
  • Define whether role-context popover needs keyboard typeahead once role count grows beyond visible rows.
  • Confirm whether clickaway dismissal needs an undo/saved-state safeguard for any future editable modal.
