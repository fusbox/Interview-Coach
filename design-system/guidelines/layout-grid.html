Layout starts with page framing, not components

A layout system names the route frame, the task hierarchy, the persistent regions and the responsive order before surfaces are styled. The second column audits the current framing; the third treats the product as a blank-slate design problem.

Grid primitives

Primary workspace: content, table, form, prompt or preparedness map
Context rail: next action, inspector, review, filters

Wireframing passes

1. Job

Name the page job, primary user decision, one next action and what must stay visible.

2. Frame

Choose the route frame: public, app shell, form flow, dashboard, session, report or ops console.

3. Order

Block the mobile reading order first, then decide what becomes a rail, drawer, toolbar or inspector on desktop.

4. Refine

Stress-test real content, empty states, scroll, sticky regions, density and only then apply surface styling.

System rule: every view starts by selecting a frame archetype. Do not begin with cards. Start with the task, the persistent regions, the responsive order and the one action the page exists to make easier.
